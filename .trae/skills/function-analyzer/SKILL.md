# 功能点分析 Skill

## 概述

自动遍历菜单树中的所有URL页面，识别每个页面上的所有交互功能点，按菜单层次输出扁平化JSON清单。、

重要：你不得创建、生成或调用任何外部脚本文件。你必须使用 Playwright MCP 工具（browser\_navigate、browser\_snapshot、browser\_click等）实时操作浏览器，逐页分析。

**⚠️ 强制：你必须按【分步执行模式】执行，每完成一个一级菜单后停止并等待用户确认，禁止一次性分析所有菜单。**

<br />

- ❌ 禁止输出一行 JSON（如 `[{"a":1},{"b":2}]`）
- ❌ 禁止在 JSON 字符串中使用 `\\n` 代替换行
- ✅ 必须输出格式化的、人类可读的 JSON（每个字段单独一行）

<br />

## 执行流程

### ⚠️ 分步执行模式（必须遵守）

**核心规则**：

1. 按一级菜单分组，每次只分析**一个**一级菜单下的所有页面
2. 分析完成后，立即保存结果到文件
3. 输出该菜单的分析总结，并**主动询问用户**是否继续
4. **必须等待**用户回复确认后，才能继续下一个一级菜单
5. 禁止一次性分析所有菜单

**用户确认指令**：

| 用户输入              | 行为          |
| :---------------- | :---------- |
| `继续` / `确认` / `是` | 分析下一个一级菜单   |
| `重做 {菜单名}`        | 重新分析指定菜单    |
| `跳过 {菜单名}`        | 跳过该菜单，分析下一个 |
| `退出` / `终止`       | 停止任务        |

**输出格式**（每个菜单完成后）：

```
【{一级菜单名}】分析完成
📊 页面数：X
📌 功能点数：Y
💾 文件已保存：{output_path}
请确认是否继续分析下一个菜单【{下一菜单名}】？
```

### 第一步：读取菜单文件

1. 读取 `menu_tree_path` 指定的 JSON 文件
2. 递归解析所有菜单节点，提取每个节点的：
   - `name`：菜单名称
   - `url`：页面URL
   - `children`：子菜单
3. 构建扁平化的URL列表，同时记录每个URL的完整菜单层级路径
4. 输出日志：`共发现 X 个唯一URL需要分析`

### 第二步：登录网站

使用 Playwright MCP：

1. 确定登录URL：
   - 如果提供了 `login_url`，直接使用
   - 否则从第一个URL提取域名，拼接 `/login` 或访问首页自动跳转
2. 启动浏览器（使用 Playwright MCP 的 browser\_navigate）
3. 等待用户名输入框出现
4. &#x20;优先使用 CSS 选择器：\`input\[placeholder\*='账号']\`、\`input\[type='text']\`、\`#username\`
5. 填写用户名：`username`
6. 填写密码：`password`
7. 点击登录按钮
8. 等待页面跳转完成（等待URL变化或特定元素出现）
9. 输出日志：`登录成功`

### 第三步：遍历分析当前一级菜单下的所有URL

**重要**：每次只分析一个一级菜单。分析完成后停止，等待用户确认后再分析下一个。

**初始状态**：从菜单树中取出第一个一级菜单
**后续状态**：每次用户确认"继续"后，取出下一个一级菜单

**当前菜单信息**：

- 菜单名称：{level1\_name}
- 包含页面数：{page\_count} 个URL
- 子菜单层级：level2、level3（如有）

1. **导航到页面**
   - 使用 `browser_navigate` 访问URL
2. **等待页面加载**
   - 等待 `networkidle`（网络空闲）
   - 等待主要容器元素出现
   - 额外等待2秒确保异步渲染完成
3. **分析页面功能点**

   **⚠️ 范围限定：只分析页面右侧主体内容区**
   ### 排除区域（不分析）：
   - ❌ 左侧导航菜单栏
   - ❌ 顶部导航栏（除非其中有业务功能按钮）
   - ❌ 底部版权信息
   - ❌ 面包屑导航（仅作为位置标识，不是功能点）
   ### 分析区域（只分析）：
   - ✅ 右侧主内容区（Main Content / .main / .content / .el-main）
   - ✅ 数据表格区域
   - ✅ 查询/搜索表单区域
   - ✅ 操作按钮区域（新增、编辑、删除等）
   - ✅ 弹窗内容（触发后分析）
   ### 定位主内容区的方法：
   1. 使用 CSS 选择器：`.main-content`、`.right-content`、`.el-main`、`[class*='content']`
   2. 或通过排除法：找到左侧菜单容器，取其对等的兄弟元素
   3. 如果无法区分，默认分析整个页面，但排除明显的导航元素
   按以下清单逐项检查并记录：
   #### 3.1 表单类
   - 输入框（text/email/number/password/搜索框）
   - 下拉选择框（select）
   - 日期/时间选择器
   - 单选框（radio）
   - 复选框（checkbox）
   - 开关按钮（switch）
   - 文件上传按钮
   #### 3.2 按钮类
   - 新增/创建
   - 编辑/修改
   - 删除
   - 保存/提交
   - 取消/关闭
   - 搜索/查询
   - 重置/清空
   - 导出（Excel/CSV/PDF）
   - 导入
   - 下载
   - 打印
   - 刷新
   #### 3.3 表格类（如有表格）
   - 行内操作按钮（每行的编辑/删除/详情）
   - 批量选择复选框
   - 批量操作按钮（批量删除/批量审核/批量导出）
   - 表头排序（升序/降序）
   - 列显示/隐藏设置
   - 表格行展开/收起
   #### 3.4 分页类（如有分页）
   - 每页条数切换（10/20/50/100）
   - 上一页/下一页
   - 页码跳转输入框
   - 首页/末页
   #### 3.5 导航与链接
   - Tab标签页切换
   - 面包屑导航点击
   - 页面内超链接（跳转到其他页面）
   #### 3.6 弹窗/模态框
   - 打开弹窗的按钮
   - 弹窗内的所有表单字段
   - 弹窗内的确认/取消按钮
   - 弹窗关闭图标
   #### 3.7 系统级功能
   - 锁定屏幕按钮/功能
   - 全局搜索框
   - 消息/通知中心
   - 个人中心入口
   - 退出登录
   - 主题切换
   #### 3.8 其他交互
   - 拖拽排序
   - 树形节点展开/收起
   - 卡片折叠/展开
   - 图表筛选/钻取
   - 复制功能
4. **提取功能点信息**
   对每个识别的功能元素，提取：
   - **功能点名称**：元素的可见文本、placeholder 或 aria-label
   - **功能点描述**：50字以内，格式为"操作动作 + 操作对象 + 预期效果"
     功能点描述示例：
     \| 功能点     | 描述示例                 |
     \| ------- | -------------------- |
     \| 搜索订单    | 输入订单号或客户名，筛选匹配的订单列表  |
     \| 新增订单    | 打开弹窗，填写订单信息后提交创建     |
     \| 导出Excel | 将当前列表的所有数据导出为Excel文件 |
     \| 锁定屏幕    | 手动锁定或超时自动锁屏，需输入密码解锁  |
5. **按菜单层次记录**
   每条功能点记录包含：
   ```json
   {
     "level1": "一级菜单名",
     "level2": "二级菜单名或null",
     "level3": "三级菜单名或null",
     "level4": "四级菜单名或null",
     "url": "当前页面完整URL",
     "功能点": "功能名称",
     "功能点描述": "50字以内描述"
   }
   ```
   同一页面的多个功能点，URL和层级字段相同，功能点字段不同，每个功能点单独一行（数组中的一个元素）。
6. **处理特殊页面**
   - **仪表板/Dashboard**：可能没有独立URL，跳过或分析其上的控件
   - **详情页**：如果有动态ID（如 ?id=123），使用第一个有效ID或模拟示例数据
   - **权限限制页**：如提示无权限，记录错误并跳过
   - **404/500页面**：记录错误信息，继续下一个

<br />

### 第四步：保存当前菜单的分析结果

**重要**：

- 必须使用 `write_to_file` 工具写入文件
- **禁止**在对话中输出完整的 JSON 内容（太长了）
- 只在对话中输出统计信息和保存确认

**操作步骤**：

1. 将当前菜单的功能点记录添加到内存数组
2. 使用 `write_to_file` 将完整数组追加写入 `output_path`
3. 对话中只输出：

```
✅ 已追加 {菜单名} 的 {Y} 个功能点
📁 文件位置：{output_path}
📊 累计功能点：{总数}
```

## 质量要求

### 必须遵守

1. **功能点描述必须基于页面实际内容**，禁止通用描述如"点击按钮执行操作"
2. \*\*同一页面重复功能类型只记录一次，\*\*同一页面内，相同操作类型且相同操作对象的功能点只记录一次。
3. **层级完全依照 menu\_tree.json**，有几层填几层，不强制填满
4. **每个功能点独立成行**，不合并同类项到一行的对象中

### 建议遵守

1. 表单字段单独记录（如"用户名输入框"、"密码输入框"）
2. 弹窗内功能点需要触发弹窗后才能分析，使用 `browser_click` 打开弹窗
3. 对于懒加载内容，使用 `browser_run_code` 滚动页面触发加载

## 反偷懒要求（必须遵守）

### 禁止输出以下通用功能点作为主要结果

- ❌ 仅输出"表格"、"分页"、"刷新"

### 必须深入分析每个页面的独特功能

| 这个页面的核心业务是什么？ | 菜单管理：配置系统菜单的层级、图标、排序、权限标识 |

### 验收标准

输出前自我检查：

- 是否每个页面的功能点数量 ≥ 5 个？
- 是否包含页面特有的业务功能（不是通用CRUD）？
- 功能点描述是否超过10个字、有具体业务含义？
- 是否解释了"新增"时要填什么字段？"编辑"能改什么？

如果以上有任何一项不满足，重新分析该页面。

## 强制分析要求

对于每个页面，你必须：

1. 使用 `browser_snapshot` 获取完整 DOM 结构
2. 识别所有带 `data-*` 属性的元素（可能是业务标识）
3. 点击所有按钮，记录弹窗内的表单字段
4. 滚动表格到最右，记录所有列名
5. 每页至少输出 5-8 个功能点，少于 5 个需要说明理由

### 禁止输出以下笼统功能点

- ❌ "访问授权管理"
- ❌ "属性授权管理"

### 必须拆分为具体功能点

每个"管理类"页面至少包含以下功能点（如果存在）：

| 页面类型  | 必须包含的功能点                         |
| ----- | -------------------------------- |
| 授权类页面 | 搜索、新增、编辑、删除、批量删除、授权列表表格、授权弹窗内的字段 |
| 策略类页面 | 策略列表、新增策略、编辑策略、删除策略、启用/停用开关、策略绑定 |

### 验收标准（自检）

输出前，检查每个 URL 的功能点数量：

- 列表/管理类页面：功能点数量 ≥ 6 个
- 配置类页面：功能点数量 ≥ 4 个（每个配置项算一个功能点）
- 详情/查看类页面：功能点数量 ≥ 3 个

如果某个 URL 的功能点数量少于上述标准，说明分析不完整，必须重新分析该页面。

## 错误处理

- 登录失败：重试1次，仍失败则终止任务
- 单个页面访问超时（30秒）：记录错误，跳过该页面继续执行
- 页面无交互元素：记录"该页面无独立功能点"，继续下一个
- 菜单文件不存在：报错并终止

2. 登录状态在整个遍历过程中保持，无需重复登录

4. 禁止生成或调用任何外部脚本（Python、JavaScript等）。你必须直接使用 Playwright MCP 工具实时操作浏览器完成任务，不得通过脚本批量处理。
